# draw.io デザイン指針

このファイルは、draw.io を使って画面設計、構成図、フロー図を作る担当が共通で参照する指針です。

対象:
- `drawio-designer`
- `dev-orchestrator`
- `code-architect`
- 必要に応じて `design-reviewer`

## この担当を追加する理由

- 要件や設計を文章だけでなく図で共有できる
- 画面設計、ユーザーフロー、システム構成図を開発前に揃えやすい
- 設計者と実装者の認識ずれを早い段階で減らせる
- MkDocs 化する仕様書に図を組み込みやすい

## AI を使うときの基本方針

- AI は最初のドラフト生成、構造整理、図のたたき台作成に使う
- 最終的な意味、命名、接続関係、境界、責務分割は人が確認する
- 直接 `.drawio` XML を生成する場合は、draw.io の公式リファレンスに沿って妥当性を確認する
- まずテキストで図の要件を固めてから、図を生成または編集する

## ベストプラクティス

### 1. 図の前にテキスト仕様を固める

AI に図を書かせる前に、最低限以下を確定させること。

- 図の種類
- 読み手
- 図の目的
- 対象スコープ
- 含める要素
- 含めない要素
- 強調したい関係
- 出力形式

推奨入力例:
- 図の種類: 画面遷移図
- 読み手: 開発者と PO
- 目的: ログイン後の主要導線を確認する
- 含める要素: 画面、遷移条件、分岐
- 含めない要素: API 詳細、DB

### 2. 1枚に詰め込みすぎず、ページとレイヤを分ける

- 大きい図は 1 ファイル内で複数ページに分ける
- 1 ページ内で説明対象が多い場合はレイヤを使う
- 背景、注釈、システム境界、詳細要素は別レイヤに分ける
- 確定済みの背景要素はレイヤをロックする

特に向いている例:
- システム構成図
- ネットワーク図
- 画面遷移図
- 段階的に説明したい業務フロー

### 3. スタイルを標準化する

- 色、フォント、線種、角丸、コネクタのルールを揃える
- 個人の見た目設定に依存しないよう、テンプレートや既定スタイルを持つ
- 新しい既定スタイルは最小限のキーだけ上書きする

### 4. 再利用する図形はカスタムライブラリ化する

- 画面部品
- サービス境界
- 外部システム
- DB、キュー、バッチなどの定番要素
- 会社固有のアイコンや凡例

再利用頻度が高い要素は Scratchpad ではなくカスタムライブラリへ寄せる。

### 5. テンプレート化して開始コストを下げる

- 画面設計テンプレート
- C4 風の構成図テンプレート
- シーケンス図テンプレート
- 業務フローテンプレート

テンプレートには、必要なカスタムライブラリを紐付ける前提で管理する。

### 6. AI に直接 `.drawio` を書かせる場合は XML を検証する

- 可能なら draw.io の公式 Style Reference を前提にする
- `mxfile.xsd` による構造検証を行う
- 単一ページなら簡略化した `mxGraphModel` だけの生成を優先してよい
- 生成後は必ずエディタで開いて崩れがないか確認する

特に注意する点:
- 必須の root セル
- 一意な ID
- `vertex="1"` と `edge="1"` の使い分け
- スタイル文字列の形式
- 非矩形図形の perimeter 整合
- HTML ラベルのエスケープ

### 7. ソースと成果物を分けて管理する

- 元ファイルは `.drawio` を保存する
- MkDocs で使う画像は `.svg` または `.png` を別に出力する
- 仕様書からは export 済みの図を参照する
- 図の元データは Git 管理する

### 8. AI をレビュー補助にも使う

- 図が要件を満たしているか
- 画面遷移に抜けがないか
- 依存方向が不自然でないか
- 境界線や責務分割が曖昧でないか

ただし、正しさの最終判断は人が行う。

- エクスポート成果物: `docs/diagrams/exports/`

## 担当ごとの使い分け

### `drawio-designer`

- 図のたたき台作成
- `.drawio` ソース管理
- 仕様書に埋め込む図の整備

### `code-architect`

- 構成図、責務境界、依存関係のレビュー
- 図と文章設計の整合確認

### `dev-orchestrator`

- 図が必要なタスクを見極めて `drawio-designer` に委譲する
- 要件整理の後、設計前または設計中に図作成を差し込む
