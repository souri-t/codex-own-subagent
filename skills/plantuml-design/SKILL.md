# PlantUML Design

このスキルは、PlantUML を使って設計情報をテキストベースで構造化し、仕様書やレビューで再利用しやすい形にまとめるためのものです。

## 使う場面

- クラス設計を図で整理したい
- 画面や API の呼び出し順をシーケンス図で表したい
- ユースケースや業務フローを構造化したい
- 状態遷移やアクティビティを仕様として残したい
- コンポーネント構成や配置構成をテキスト管理したい
- MkDocs に埋め込みやすい図のソースを Git 管理したい

## 基本方針

1. 先に要件、目的、読み手、図の範囲を文章で固める
2. 図の種類を明確に選ぶ
3. 1つの図に責務を詰め込みすぎない
4. `.puml` ソースを正本として管理する
5. 画像は成果物として export し、仕様書から参照する

## 図の選び方

### クラス図

使う場面:
- ドメインモデル
- DTO / record の整理
- 依存関係
- 責務分割

### シーケンス図

使う場面:
- API 呼び出し順
- ユーザー操作から内部処理までの流れ
- 外部システム連携

### ユースケース図

使う場面:
- 利用者ごとの機能整理
- スコープ確認

### アクティビティ図

使う場面:
- 分岐を含む業務処理
- バックエンド処理フロー

### 状態遷移図

使う場面:
- ステータス管理
- ワークフロー
- ライフサイクル設計

### コンポーネント図 / 配置図

使う場面:
- システム構成
- サービス境界
- 実行環境

## 進め方

1. 図の目的を 1 文で書く
2. 登場要素を列挙する
3. 要素間の関係だけを先に箇条書きにする
4. PlantUML に落とす
5. 過密なら図を分割する
6. 仕様書本文と図の名前を揃える

## 出力ルール

- 図を出す前に、何を表す図かを短く説明する
- PlantUML ソースは読みやすさを優先して整形する
- 図名とファイル名は対応させる
- 生成した図だけでなく、前提や省略点も文章で補う

## 保存先

- PlantUML ソース: `docs/diagrams/plantuml/`
- export 画像: `docs/diagrams/exports/`

## 推奨ファイル例

- `docs/diagrams/plantuml/domain-model.puml`
- `docs/diagrams/plantuml/login-sequence.puml`
- `docs/diagrams/plantuml/order-state-machine.puml`
- `docs/diagrams/exports/domain-model.svg`

## レビュー観点

- 図の責務が 1 つに絞られているか
- 図と仕様書本文の用語が一致しているか
- 矢印や依存方向が誤解を招かないか
- 実装詳細と設計意図が混ざりすぎていないか

## draw.io との使い分け

- PlantUML:
  テキストで再現可能な設計図、差分レビューしやすい図、構造図、振る舞い図に向く
- draw.io:
  画面設計、レイアウト、自由度の高い構成図、視覚調整が重要な図に向く

## 生成時の実務ルール

- 先に小さな図から始める
- 分割できる図は複数ファイルに分ける
- 仕様書中の見出しとファイル名を対応させる
- review で指摘が多い図はテンプレート化を検討する
